## 1. V0 — Groundwork & decision gate

- [x] 1.1 GGUF tensor inventory (from the inference audit / gguf-dump): attn `q_a`[1024,4096]·`q_b`[1024,32768]·`kv_latent`[4096,512]·`output_a`[4096,8192]·`output_b`[8192,4096] (all Q4_K), HCA `attn_compress_kv/gate`[4096,512] Q4_K + `compress_ape`/`norm` F32, indexer `attn_q_b`[1024,8192] Q4_K + `compress_*` Q4_K + `proj`[4096,64] Q4_K, mHC `hc_*_fn`[16384,24] F32, MoE exps Q4_K + `ffn_down_shexp` Q6_K, norms/sinks/`gate_inp` F32, `gate_tid2eid` I32 (first 3 layers).
- [x] 1.2 FP8-KV decision: FP8 is a **runtime KV-cache** quant (`dsv4_fp8_kv`), not a stored weight — extraction has no FP8 tensor to store; it stores the Q4_K/Q6_K/F32 weights as-is and FP8-KV stays a runtime concern of the (existing) inference path. So no FP8 format support is needed in the vindex.
- [x] 1.3 Capabilities: added `ModelArchitecture::uses_dsv4_attention()` (default false; `true` for `DeepSeekV4Arch`) and a DSv4 branch in `capabilities.rs` that gates DSv4 out of the standard Q/K/V/O writers with a **distinct** feature message (DSv4 was previously not MLA-flagged, so it silently fell into the broken standard writer). 5 new tests; V2/V3 still MLA-rejected, llama still passes. The gate **flips to accept** when the DSv4 writer lands (V1+) — until then this is a clean reject, not the spec's end-state "accept".

## 3. V2 — HCA compressor + indexer

- [x] 3.1 `dsv4_hca.bin` wire format (`crates/larql-inference/src/attention/dsv4_vindex_hca.rs`, magic `D4HC` v1): `DsV4HcaWeights { compressor: Option, indexer: Option }`. Compressor (gated `compress_ratio>0`) = `attn_compress_kv`/`gate` raw-Q4_K passthrough + `ape`/`norm` f32. Indexer (gated `compress_ratio==4`) = its sub-compressor (`indexer.compress_*`) + `indexer.attn_q_b` raw-Q4_K + `indexer.proj` (Q4_K, stored **raw** to stay byte-faithful even though the resident loader currently dequantizes it). Top-k masks NOT stored (selection stays runtime-dynamic). Wire primitives extracted to shared `dsv4_vindex_wire.rs` (Cursor/put_raw/read_raw/f32-vec/header + `DsV4VindexWireError`); V1 `dsv4_vindex_attn.rs` refactored onto it (its 4 tests still green → refactor verified safe). V3 mHC reuses the same wire.
- [x] 3.2 Variant-aware round-trip: synthetic CI tests (`compressor_only_round_trips` = Compress, `indexer_layer_round_trips` = Indexer, `nocompress_layer_round_trips` = NoCompress→7-byte blob, `malformed_blobs_are_typed_errors`). Real-GGUF `#[ignore]` gate `real_gguf_hca_round_trips_to_storage`: scans for a Compress + an Indexer layer, reads their HCA/indexer weights via the *same* readers the resident loader feeds, round-trips, asserts byte/type/shape equality on every raw tensor + f32 equality on ape/norm — compressor only for the Compress layer, compressor+indexer for the Indexer layer.

## 4. V3 — mHC + MoE + head

- [x] 4.1 `dsv4_mhc.bin` wire format (`crates/larql-inference/src/attention/dsv4_vindex_mhc.rs`, magic `D4MH` v1): `DsV4MhcWeights { attn, ffn, head: Option<MhcBookend> }` — per-layer blobs set `attn` + `ffn` (`hc_attn/ffn_{fn,scale,base}`), the model-level head blob sets `head` (`hc_head_{fn,scale,base}`). All bookends are f32 (no quantized passthrough); `hc_fn`'s 2D shape and `hc_base` length are recovered from `hp` on read, so only flat values are stored (scale is `[3]` per-layer, `[1]` for the head). Built on shared `dsv4_vindex_wire`. Synthetic CI tests (layer / head / empty / malformed) + real-GGUF `#[ignore]` gate `real_gguf_mhc_round_trips_to_storage` (layer 0 attn/ffn via the per-layer f32 reader + head via `load_dsv4_head`, round-trip, assert bit-exact + hp-derived shapes).
- [x] 4.2 `dsv4_moe.bin` wire format (`crates/larql-inference/src/attention/dsv4_vindex_moe.rs`, magic `D4MO` v1): routed experts `ffn_{gate,up,down}_exps` (raw Q4_K 3D) + shared expert `ffn_{gate,up}_shexp` (Q4_K) / `ffn_down_shexp` (**Q6_K** — preserved by raw passthrough) + router `ffn_gate_inp` (f32) + `ffn_norm` (f32) + optional `exp_probs_b` bias (f32) + optional `ffn_gate_tid2eid` hash table (i32, first-3 layers). Shared wire gained `put/read_i32_vec` + `_opt_` variants. Synthetic CI tests (gated / hash / malformed) + real-GGUF `#[ignore]` gate `real_gguf_moe_round_trips_to_storage` that scans for a hash-routed + a gated layer, reads via the same readers the resident loader feeds, round-trips, and asserts byte/type/shape on every expert (incl. Q6_K down-shexp) + gate/bias/norm/hash-table equality — confirming the hash table + bias survive.
- [x] 4.3 `dsv4_head.bin` wire format (`crates/larql-inference/src/attention/dsv4_vindex_head.rs`, magic `D4HD` v1): `token_embd.weight` (raw, quantized) + `output.weight` lm-head (raw, quantized, `Option` for tied-embedding models) + `output_norm.weight` (f32). The global head mHC (`hc_head_*`) rides in the mHC format's `head` field (4.1), not here. Added a reusable global raw reader `read_dsv4_named_raw_tensor(gguf, name)` (the per-layer `blk.N.*` schema doesn't cover global tensors). Synthetic CI tests (untied / tied / malformed) + real-GGUF `#[ignore]` gate `real_gguf_head_round_trips_to_storage` (token_embd + output via the global raw reader, norm via `load_dsv4_head`, round-trip, assert byte/type/shape; quantized embed/lm-head don't degrade to f32). Backs the head/embed clause of the V4 whole-model round-trip scenario.

## 5. V4 — End-to-end extraction + round-trip + serving reader

- [x] 5.1 Full-model extraction orchestrator `build_dsv4_vindex` (`crates/larql-inference/src/attention/dsv4_vindex_build.rs`). **Architecture note:** `larql-inference` depends on `larql-vindex` (one-way), so the generic `build_vindex` (in larql-vindex) *cannot* call the DSv4 writers (in larql-inference) — circular. DSv4 therefore gets a **dedicated** extraction entry point here, and larql-vindex's generic capabilities gate **correctly keeps rejecting** DSv4 (the generic Q/K/V/O writers can't represent low-rank/latent/grouped attention). The spec's first requirement/scenario were updated to match. On-disk layout: flat dir with `index.json` (`DsV4VindexManifest`: format/version/model_id/n_layer/`compress_ratios`), `head.bin` (D4HD), `mhc_head.bin` (D4MH head-only), and `blk.<i>/{attn,hca,mhc,moe}.bin`. Per-layer reads reuse the same GGUF readers the resident loader feeds; variant gating (compressor cr>0, indexer cr==4) falls out of the absent-kind-skipping raw reader. Real-GGUF `#[ignore]` test produces the full ~161 GB artifact.
- [x] 5.2 Round-trip reader (`read_dsv4_vindex_layer`/`_head`/`_manifest`) loads the produced blobs back into the extraction structs. CI test `vindex_dir_round_trips` (2 layers — gated + indexer — + head + manifest written to a tempdir and read back identically). Real-GGUF `#[ignore]` gate `real_gguf_full_vindex_round_trips` builds the full vindex, then reads every layer's blobs back and asserts byte/shape equality (q_b, Q6_K down-shexp, hash table, indexer presence) + head vs fresh GGUF reads. Full **`DsV4LayerWeightStorage` reconstruction** (rebuilding `QuantTensor`s + `CompressorStorage`/`IndexerStorage`/`MhcStorage`/`FfnStorage`) is the serving reader's job — see 5.3 hand-off.
- [x] 5.3 `make ci` green (fmt/clippy/tests/traceability/openspec). Re-eval reminder (carried from V1 gate): a faithful vindex carries identical Q4_K bytes → same decode bandwidth floor as GGUF-direct; the win is cold-start/RSS + architectural consistency, not throughput.
- [x] 5.4 **Serving reader** (`crates/larql-inference/src/attention/dsv4_vindex_load.rs`) — the consumer the arc was missing. `load_dsv4_vindex_resident(dir, hp)` reconstructs `DsV4LayerWeightStorage[]` + `DsV4HeadStorage` from the produced vindex, ready for `dsv4_resident_generate_with_prefix_cache`. **Reuse, not reimplementation:** `layer_vindex_to_maps` re-assembles the `(f32, raw, int)` `HashMap`s the blobs hold and calls the *existing* `build_layer_storage_resident`, so reconstructed storage is identical to a direct GGUF resident load by construction. One asymmetry handled: `indexer.proj` is stored raw (byte-faithful) but f32 in the resident layout → dequantized on load; head `token_embd`/`output.weight` likewise dequantized. CI test `map_routing_places_kinds_correctly` (asserts raw vs f32 vs int routing + the IndexerProj dequant); real-GGUF `#[ignore]` gate `real_gguf_vindex_storage_equals_gguf_resident_load` builds a vindex then asserts reconstructed storage == `load_dsv4_resident_layer(gguf)` (variant + `wq_b_quant` raw bytes + norms + head). Folding `DsV4VindexMeta` into `index.json` + an mmap'd big-blob layout + server wiring (#152, blocked on the vindex-only server) remain follow-ups.

## 6. Server wiring (#152 — vindex-conforming path)

The HTTP server is vindex-only (`bootstrap.rs::load_single_vindex` builds `LoadedModel` from a semantic `VectorIndex` + `VindexConfig` + embeddings + tokenizer; zero GGUF awareness) and hard-rejects `deepseek_v4` at `chat.rs`. Making DSv4 reachable is a multi-PR epic on the vindex-conforming path:

- [x] 6.1 **Server-conforming metadata emission.** `build_dsv4_vindex` now also writes `index.json` as a real `VindexConfig` (family `deepseek_v4`, DSv4 hyperparams in `model_config.dsv4` via `dsv4_meta_from_hp`, incl. the `hp.yarn`→`DsV4YarnMeta` + `DsV4RopeMode`→string maps) + `embeddings.bin` (dequantized `token_embd` → raw f32 `[vocab, n_embd]`); the DSv4-internal manifest moved to `dsv4_manifest.json`. CI test `server_config_and_embeddings_parse_via_vindex_loaders` round-trips through the *actual* `larql_vindex::load_vindex_config` + `load_vindex_embeddings`.
- [x] 6.2 `tokenizer.json` emission: `write_dsv4_tokenizer(root, src)` copies the model's HF `tokenizer.json` into the vindex (no GGUF→HF converter exists in-repo, so a faithful copy); `build_dsv4_vindex` gained an `Option<&Path> tokenizer_src` arg. Completes the server-required metadata trio (`index.json` + `embeddings.bin` + `tokenizer.json`). CI test `tokenizer_is_copied_byte_faithfully`. (Real HF tokenizer sourcing for DSv4-Flash is a deployment detail at artifact-build time.)
- [~] 6.3 Bootstrap tolerance — **mostly pre-handled**: `VectorIndex::load_vindex_with_range` already has a graceful both-missing branch ("attention-only client-side slice") that synthesizes empty `num_features: 0` gate slices when neither `gate_vectors.bin` nor `interleaved_q4k.bin` is present — exactly the DSv4 case. So a weights-only DSv4 vindex loads with an empty semantic index; no `family == "deepseek_v4"` server branch is needed there. Remaining for 6.3: a `DsV4VindexMeta` → `DsV4Hyperparams` reconstruction (needed by 6.4 so the server rebuilds `hp` without the GGUF) + a larql-server integration test that `load_single_vindex` builds a `LoadedModel` from a DSv4 dir. - [x] 6.4a `DsV4VindexMeta` → `DsV4Hyperparams` reconstruction (`dsv4_vindex_load::dsv4_hyperparams_from_meta`, the inverse of `build::dsv4_meta_from_hp`, now `pub`): maps the scalar set + `rope_mode` string→enum + `yarn` `DsV4YarnMeta`→`DsV4RopeYarnConfig`, so a vindex-only server rebuilds `hp` from `index.json` without the GGUF.
